Bitrate, duration and repeated compression

File size is close to bitrate multiplied by duration. Resolution affects how much detail those bits must carry. A busy shot with water or leaves needs a different setting from a still interview. Lower the bitrate on a short copy and watch for blocks or smeared motion before changing the frame size.

Each lossy encode discards information. Return to the camera file for another attempt instead of compressing the last compressed copy. See bitrate versus resolution for the setting tradeoff.

Questions about this comparison

Can a compressor guarantee an attachment will fit from resolution alone?

No. Duration and bitrate affect the size. Set a size target, inspect the export size and check that the receiving service accepts the format.

Why can a quiet interview shrink more than moving water?

The picture changes less between frames. Water, snow and fine moving texture give an encoder more change to describe, so a setting that suits an interview may smear those scenes.

Should I compress the compressed copy again after a failed upload?

Return to the original and change the settings there. Repeated lossy exports discard more information each time.

Is an upload cap the same as a processing allowance?

No. A web service may limit file bytes, processing minutes and daily uses separately. Check each limit in the row before sending a large file.
